# Surveys

Admins build, translate and publish short surveys; participants answer them on phone or desktop and get a reward. BASF Advisor Advantage pilots v1.

This group holds the **participant side** and the **shared question components**. The admin builder, French editor and results come in a later pass. The plan and every deviation from the wireframes are in `docs/survey/shell-mapping.md`.

## How it behaves

- **Phone-first, one question per screen.** Single choice, yes/no, rating, opinion scale and NPS auto-advance after a tap; the rest use Next, pinned to the bottom on phones.
- **Layout follows the space it's given.** Components use container queries, so a phone frame inside a desktop page (the builder's Mobile preview) gets the phone layout.
- **Keyboard on desktop.** A–Z to pick, number keys for scales (1 then 0 for 10), Enter to continue, up/down arrows to move between questions. Shortcuts never fire while typing in a field.
- **Accessible.** Selection is never shown by colour alone, targets are at least 48px on phones, focus moves to each new question's title, and messages are inline.
- **Autosave and resume.** `SurveyPlayer` calls `onResponseChange` after every answer and resumes in-progress responses at the next unanswered question on the participant's logic path.
- **Paid once.** `SurveyPlayer` blocks double submits; the platform must also make the payout idempotent on survey + participant.
- **English and French.** Pass a resolved survey per language. Question and option IDs are shared, so answers line up in exports.

## Quizzes

A quiz is a survey with right answers (`kind: "quiz"`), chosen when it's created. Multiple choice, dropdown and yes / no questions can be scored; other types are collected but not scored. Each quiz sets a pass mark, a reward rule (on completion, on passing, or tiered by score) and when answers are shown (after each question, at the end, or never). Quizzes are identified and can't be retaken. The rules live in `quiz-logic.ts`; the platform should grade on submit with the same rules. Details are in `docs/survey/shell-mapping.md`.

## For the platform team

Components take typed data (`survey-types.ts`) and callbacks. Nothing here talks to a server. Wire these to the API:

- `onResponseChange(response)`: autosave. For anonymous surveys, keep the resume link in a short-lived server-side mapping that never reaches admin data.
- `onSubmit(response) → { reward }`: mark complete and pay the reward once.
- `onExit`, `onNavigate`: leave the takeover.
- `getSurveyAvailability(survey, response, now)`: open, not open, closed (with a 24-hour grace period to confirm) or completed.
